# 01 — MDSE Core: Detailed Tool Definition

**Tool boundary:** Shared library for model-note syntax, identity-related helpers and byte-preserving edits. It is not an Obsidian screen, importer, file repository or release manager.

**Authoritative model:** [[50_Architecture/MDSE Core/MDSE Core|MDSE Core]] (OBJ-00002; one reusable tool definition); its child definitions are [[50_Architecture/MDSE Core/Note and SysML Codec|Note and SysML Codec]] and [[50_Architecture/MDSE Core/Model Identity Lookup|Model Identity Lookup]].

**Source:** [tools/core](https://github.com/spencerskelly/MDSE_v2/tree/main/tools/core), notably [mdse_core.js](https://github.com/spencerskelly/MDSE_v2/blob/main/tools/core/src/mdse_core.js) and [bom_own.ts](https://github.com/spencerskelly/MDSE_v2/blob/main/tools/core/src/bom_own.ts). **Governing rules:** MOD and the shared architecture contract. **Source status:** usable JavaScript helpers with tests; the older Core README acknowledges uncompleted TypeScript/merge-policy reconciliation. Treat those as unresolved, not silently fixed.

## 1. Purpose and success condition

A note generated by Importer and later inspected/modified by Workbench must retain **one stable identity** and one consistent interpretation of its YAML, human-authored Markdown and authoritative SysML v2 text. Core is the common codec so two tools do not invent different note meanings. Success means a recognized valid note round-trips consistently and an intended edit affects only the authorized region.

## 2. Inputs, outputs and operating boundary

| Input | Processing | Result |
|---|---|---|
| Markdown note string | Parse YAML and model sections | Structured metadata and model text |
| Element-type/class schema | Validate class, subtype, required properties | Diagnostics, not inferred model semantics |
| Existing note and replacement SysML block | Preserve the preceding note bytes; replace authoritative section | Proposed updated note text |
| Existing frontmatter with a controlled change | Apply a specific property change | New note text/diff for caller approval |
| Note with flag callout | Remove the selected flag only when requested | Revised text for caller verification |
| List of output files | Package a new-vault bundle | ZIP bytes for the caller |
| BOM-owned SysML contents | Resolve usage ownership/member hashes | Reconciliation inputs, not an independent BOM database |

Core accepts text/bytes and returns text/bytes or structured results. Folder selection, browser permission, Obsidian workspace leaves, GitHub/Jira and engineer approval belong elsewhere.

## 3. Canonical model-note contract

- **Identity:** the YAML uid is stable and more authoritative than a filename or folder path; modeled class IDs follow the class schema. Do not manufacture a second identity for a moved note.
- **Metadata:** YAML frontmatter holds administrative properties and source provenance. It is not a second authoritative store for native SysML semantics.
- **Human-authored body:** the user zone is retained when an importer or editor changes managed content. Manual explanation, rationale and evidence must not be lost during reimport.
- **Source content:** translated EA notes can contain a managed Source: EA section and provenance; source rows do not automatically imply approved SysML relationships.
- **Native model:** the final SysML v2 section contains the owned native model text. For relationship/structure changes, that block is authoritative; Workbench views and YAML projections are derivative.
- **Validation:** a lightweight scanner/checker is not the independent SysML parser. Unknown or unresolvable semantics remain flagged.

## 4. Internal responsibilities

### A. Note and SysML Codec

The code exposes parse, section extraction, SysML extraction, validation, replaceSysmlBlock, frontmatter patching, flag removal and ZIP helpers. It must avoid a regenerated entire note if only a controlled region changed. See [[50_Architecture/MDSE Core/Note and SysML Codec]].

### B. Model Identity Lookup

The model definition assigns identity lookup here. In practice, duplicate/legacy identity, EA GUID matching and BOM PN matching also involve Importer planning and Workbench indexing. Core should own stable identity semantics, while the caller owns any specific source registry and filesystem search. The final split remains subject to source review. See [[50_Architecture/MDSE Core/Model Identity Lookup]].

### C. BOM-owned member utilities

The newer bom_own.ts carries BOM usage/member inspection and owned hashing utilities. These support Importer/Workbench comparison; they do **not** make Core the owner of a production BOM or revision approval policy.

## 5. Key interfaces

**From Importer:** validation and serialization for generated notes; protection of an existing user zone; controlled diffs/merge decisions resolved by Importer.  
**From Workbench:** parse model notes and proposed transactional edits; return a diff, then write only after user-approved Apply.  
**To Base Vault:** model-note template/class compatibility; Core does not choose the distributed templates.  
**To Bootstrap:** potential author/identity helper; Bootstrap still owns prompting and the person note.

## 6. Correctness and safety rules

1. Do not overwrite filled properties or an existing SysML block without the governing approved transaction.
2. Never treat a YAML display projection as a second native relationship when the SysML block already owns it.
3. Never silently drop a source row, identity, user explanation or unresolved endpoint.
4. Preserve exact note identity across rename/move and repeated import.
5. Reject a mismatched type/UID or mark it for explicit review according to the approved conflict policy.
6. Do not equate internal syntax checks with parser certification.

## 7. Tests and acceptance criteria

- **CORE-01:** Valid notes parse; invalid classes, malformed frontmatter and malformed SysML framing report diagnostics.
- **CORE-02:** Replace one SysML block and prove every byte above it remains unchanged.
- **CORE-03:** Idempotent parse/serialize and no duplicate SysML sections.
- **CORE-04:** Model identity remains stable when filename/path changes.
- **CORE-05:** Caller-approved change preserves human-authored content and flags unapproved conflicts.
- **CORE-06:** Verify BOM-owned member hashes against representative structural usages and revisions.
- **CORE-07:** Cross-check note-format behavior against independent Python oracle and test generated model with an independent pinned SysML parser.

**Existing automated evidence:** [Core unit tests](https://github.com/spencerskelly/MDSE_v2/tree/main/tools/core/test), [cross-check oracle](https://github.com/spencerskelly/MDSE_v2/blob/main/testing/oracles/test_core_crosscheck.py). The PR #10 suite passed, but no claim is made here for real installed-vault acceptance or that the legacy merge semantics have been corrected.

## 8. Open design items and scope exclusions

- **Requires reconciliation:** the retained Core mergeNote previously refreshed source/SysML fields automatically while Importer's merge policy requires engineer approval; do not use that old routine as independent permission to overwrite engineering data.
- **Requires reconciliation:** Core README describes the TypeScript port as outstanding while a TypeScript BOM helper now exists; avoid calling the entire Core implementation TypeScript.
- **Open:** ownership of identity for individual SysML usage occurrences (OD-03).
- **Out of scope:** source file parsing, user-facing Workbench views, plugin lock verification, engineering change approval, cross-vault operations and revision release.
