# last+check

Review of every MDSE repository under `spencerskelly` for work that was neither carried into MDSE_v2 nor explicitly refused. Anything worth keeping is rewritten as a stakeholder need, use case, behavior, object or requirement note in `notes/`. Everything else gets a ledger row saying why it stays behind.

Branch: `last+check`. Baseline compared against: MDSE_v2 `d35af12` (2026-10-21). MDSE_v2 keeps moving, so each ledger is valid for the baseline it names.

## Method

1. Take stock of what MDSE_v2 has: `governance/RULESET.md`, `governance/DECISIONS.md`, `docs/HISTORY.md` (what came across and what was left behind on purpose).
2. Go one repo at a time, one folder at a time. For each file record one disposition:

| Disposition | Meaning |
|---|---|
| CARRIED | The substance is in MDSE_v2 (rule ids named in the basis) |
| REFUSED | Explicitly superseded, retired or declined (decision or register row named) |
| EVIDENCE | A record of a past run. Not a rule. HISTORY.md already leaves these behind |
| NOTE | Valuable and not carried. Rewritten as a note in `notes/` (ids listed) |
| UNREVIEWED | Not yet looked at |

3. Each ledger row also states how deeply the file was reviewed: `read`, `partial`, `headings`, `title`, `id-crosscheck`, or `none`. A `title` row was judged from its name and neighbours, not read.

## Notes

- Class prefixes follow `governance/schemas/element-types.yaml`: stakeholder needs are Requirement/stakeholder (`STK`), requirements are Requirement/engineering (`REQ`), plus `BEH`, `UC`, `OBJ`.
- Ids are in the range 98001 and up (90 notes; REQ ids 98001 to 98069, plus STK, BEH, UC and OBJ). The range keeps these notes clear of the sequential ids the EA import will allocate (MOD-015, no gaps) and of the fixture range 99000 to 99999. The range is provisional.
- Author code is `skellyspencer`, since the owner directed the work. uids run forward from 2026-10-21 21:20:00.000 local.
- Status is Draft. Where the source only proposed something, the note carries a `flagNote`.
- SysML blocks are minimal and have not been through the parser check.
- No product data. Notes describe the toolset and process only.
